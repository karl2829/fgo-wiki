# 从者卡生成规则（定版 2026-11-25）

> 本文是**唯一权威**的生成口径。改版式/改展示规则先改这里，再改代码。
> 相关：`build_data.py`（数据）、`make_card.py`（渲染）、`templates/servant_card_data.html`（版式）、`cardkit/`（渲染内核）。

## 1. 引擎

- **pytakumi**（HTML/CSS → Skia），不起浏览器进程；简单拼图走 PIL（徽标、裁切、校验）。
- CSS 逻辑宽 1080px，`dpr=2`，`bleed=40` → 输出宽 2200px，高随内容自适应（不清零空白）。
- 中文字体必须显式注入（`cardkit.render.fonts()` 读 wqy-zenhei）；`::before/::after` 不可用，装饰写真实 div。

## 2. 数据源

- **唯一数据源：`~/fgo-wiki` 的实体 MD**，不做补算、不猜规则。
- 中文内容取 `entities/servants/CN/<内部ID>.md`；**日文内容取 `entities/servants/JP/<内部ID>.md`**（2026-11 起 JP 从者全量存在）。
- `raw/servants/{CN,JP}/<id>.json` 只用于 **技能 id 配对**（CN 中文名 → id → JP 日文名）与**宝具读音 ruby**，不直接进版式。
- 数据口径按 API：`减少敌方全体充能 0.1%` 保留原值，不换算成「1 格」。

## 3. 生成流程

```bash
cd ~/card-render
.venv/bin/python build_data.py <内部ID>              # → data/<内部ID>.json（含资产下载）
.venv/bin/python make_card.py <内部ID> -o out/x.png --no-art
bash /home/mila/ops/publish_image.sh "$PWD/out/x.png"  # → https://gen.karlhub.cn/<时间戳>_x.png
```

- `build_data.py --no-assets` 会跳过立绘/职阶图标同步，**重建时别带**（否则图标缺失）。
- 发布文件名带 `YYYYMMDD-HHMMSS` 前缀，防浏览器缓存。

## 4. 效果展示规则（四态，定版）

| 数据形态 | 展示 |
|---|---|
| 随等级变化（技能 Lv.1–10） | **十格**数值条，Lv.1 / 6 / 10 底部金线（6 级不再加框） |
| 随 OC 变化（宝具 1–5） | **五格**数值条 |
| 恒定值（有数字、无等级表） | **通栏单格**，数值居中（技能 `.vb1`／宝具 `.vb5-fix`） |
| 完全无数值（纯描述） | **通栏单格 + `∅`**，居中、淡色（`.vb-empty`） |

- **缺失即缺失**：wiki/API 没有数值就显示 `∅`，不补算、不用估算值填。
- 充能时间放技能行右侧；**不显示**技能断点说明、不显示宝具档位标注（Lv.1–5 / 100%–500%）、不加固有技能块。

## 5. 区块顺序与版式

- 上：从者区（立绘 + 名字 / 日文名 / ATK·HP / 指令卡 / 羁绊礼装 / 六维 / 特性）。
- 中：**宝具区**；下：**持有技能区**（宝具在上、技能在下）。
- 左栏立绘与右栏信息**大前提等高**，不靠固有技能凑高度。
- 页脚：`No.{{图鉴编号}} | ★N 徽标 | 画师 | 声优`，字号偏小偏淡，看过一遍不需再注意。
- 特性行金色词 = 羁绊礼装加成条件（含 `秩序女`/`秩序善`/`持有灵衣之人` 这类推导出的条件），按从者动态生成。

## 6. 日文名（2026-11 新增）

- 从者：中文名为主，下行小字日文名。取 JP MD `# 名称`；若该字段被人工改成中文（不含假名 `\u3040-\u30ff`），退回基础信息表的「原始名称（日文）」。二者相同则整行不显示。
- 宝具：中文名为主，副名 = `日文原名 ／ 读音`（JP `originalName` ≠ `name` 时取原名 + `ruby`）。
- 技能：中文名后跟日文小字 + 等级。日文名用 **CN raw「中文名 → id」→ JP raw「id → 日文名」** 配对；查不到（日服已强化换代，如 カリスマ→理想郷の騎士）退回「等级 + 充能 + 全部效果数值链」签名匹配。**禁止用索引对齐**——CN raw 的 `skills[]` 混有强化前旧技能。

## 7. 资产

| 资产 | 命名 | 来源 |
|---|---|---|
| 立绘 | `art_<内部ID>.png` | **素材库** `~/fgo-wiki/assets/servants/art_<id>.png`（缺失才从 Atlas 下载并落库），再复制到 `card-render/assets/` |
| 羁绊礼装 | `bond_ce_<内部ID>.png` | 同上，库内命名 `bondce_<id>.png` |
| 星级徽标 | `badge_<rarity>.png` | PIL 自绘 |
| 小金星 | `stars_<n>_<tier>_glow.png` | PIL 自绘 |
| 职阶图标 | `{职阶小写}_{gold|silver|bronze}.png` | **素材库** `~/fgo-wiki/assets/classes/`，色阶按星级（≥4 金 / 3 银 / 其余铜）；jsdelivr 已弃用 |
| 指令卡/技能图标 | `card_{Q,A,B}.png`、`skill_*.png` | `~/fgo-wiki/assets/{cards,skills}/` |

## 8. 数值口径

- ATK / HP 与等级标签：扫 MD 里 `满级攻击力(Lv.N)` 取**最大值 N**（1★60 / 2★65 / 3★70 / 4★80 / 5★90），再取该级数值。**不能写死 90/80**。
- 六维、NP 获得率、出星率等按 MD 原值直出，不做换算。

## 9. 已知数据缺口（不补，按 ∅ 显示）

- wiki 存在「只有效果名、没有数值表」的条目（如摩根 `暴击星集中度提升`、斯巴达克斯 `付与自身毅力状态`）。核查后决定：**以 API/wiki 为准，缺失就显示 ∅**，不自作主张回填。
